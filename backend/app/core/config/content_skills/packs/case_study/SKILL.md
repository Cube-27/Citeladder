## Purpose

Use when supplied context contains real first-party evidence about a customer, implementation, project, process, before/after state, or result.

## Structure

1. Descriptive title.
2. Customer/project snapshot.
3. Starting challenge or situation.
4. Approach or implementation.
5. Result/outcome.
6. Metrics/evidence where supplied.
7. Lessons, applicability, or why it matters.
8. Relevant CTA.

## Tone

Evidence-led, concrete, restrained.

## Craft rules

- Preserve exact metrics and dates.
- Explain the starting state so the result has meaning.
- Separate observed results from causal claims.
- Use customer quotations only when exact quotations are supplied.
- If metrics are absent, write a qualitative case study rather than inventing ROI.
- Keep promotional commentary subordinate to evidence.
