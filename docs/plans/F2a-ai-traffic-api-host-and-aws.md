## Design

### A. Enablement

1. `entitlements.json`: add flag `crawl_logs` (`public: true`, label "AI
   crawler logs"), bump `registry_revision` to `entitlements-v5`. Add
   `{key:'crawl_logs', value:1}` to every plan bundle in
   `catalog-authoring.ts`. `public_trial.grants` unchanged.
2. Replace every crawl-log `hasDevelopmentWorkspace` call with
   `requireGrantedFlag(db, workspaceId, 'crawl_logs', refusal)`; refusal code
   `crawl_logs_not_in_plan` (add to the contracts error-code list and
   `docs/api-error-contract.md` if codes are enumerated there).
   `ingestion_enabled: true`; it remains the global kill switch (false →
   409 `crawl_logs_disabled`).
3. `crawlSourceListSchema` (`packages/contracts/src/ai-traffic.ts` ~:207-229):
   replace `ingestion_enabled: boolean` with
   `availability: 'available' | 'not_in_plan' | 'disabled'`. UI maps
   `not_in_plan` → upgrade alert with link to `/settings?tab=…billing`
   (use the existing billing route), `disabled` → "Collection is paused by
   CiteLadder" alert.
4. `stalled` state: columns on `crawl_log_sources`: `stall_reason
   varchar(32) NULL`, `stalled_at timestamptz NULL`. Reasons:
   `no_receipts` (live source with no accepted receipt for
   `stalled_after_hours`, config default 24, evaluated in `crawlLogTick`),
   `not_in_plan`, `oversize` (Firehose 413 seen), and later F2b reasons. An
   accepted receipt clears the stall in the same transaction. Read model
   exposes `state: 'active' | 'stalled' | 'revoked' | …` (extend the
   existing state union) plus `stall_reason`.
5. Bytes ceiling: config `received_bytes_per_project_per_day` (default
   2147483648). Count decompressed bytes on receipts per project per
   reporting day; above it return 429 with `Retry-After` = seconds to the
   next reporting-day start and write a diagnostic receipt
   `bytes_ceiling`. Enforce in `batchQuota` beside the existing quotas.

### C. AWS: CloudFront v2 → Firehose → CiteLadder

Follow tracker section F2 "part B" exactly for flow, request handling order,
response contract and status mapping. Specifics:

- Source setup `aws_firehose`, `kind: webhook`, preset `cloudfront_v2_json`,
  `collection_point: cdn_edge`. Column `buffer_interval_seconds int NULL`
  (60–900, required for `aws_firehose`).
- Adaptor `src/crawl-logs/firehose.ts`: translates and calls `ingest()`;
  never writes rows itself. Token only from `X-Amz-Firehose-Access-Key`
  (constant-time hash compare as Bearer). Idempotency key
  `firehose:<requestId>`. Response JSON `{requestId, timestamp[, errorMessage]}`,
  `Content-Length` set, no `Content-Encoding`. Never 3xx.
  Status map: accepted/replayed 200; `unsupported_format` 400; bad token 401;
  quota/bytes ceiling 429; over 5 MiB 413 (+ `oversize` diagnostic receipt and
  stall reason); disabled/not active/not in plan 409; unexpected 500.
- Preset `cloudfront_v2_json` in `crawl-logs.json` and the contracts mapping:
  `timestamp(ms)` (string epoch ms; add string→number coercion for
  `timestamp_unit: "milliseconds"`; fallback `date`+`time` UTC), host
  `x-host-header` (not `cs(Host)`), path `cs-uri-stem`, method `cs-method`,
  status `sc-status`, UA `cs(User-Agent)` with new `user_agent_decode: "url"`,
  client IP `c-ip` (transient), request id `x-edge-request-id`. `"-"` →
  missing in every field (new mapping option `missing_tokens: ["-"]`).
  Build the test fixture from the CloudFront v2 field list in the tracker
  appendix; mark in the docs guide that UA decoding was verified on fixture.
- Coverage: per-source gap bound
  `max(max_delivery_gap_minutes, ceil(buffer_interval_seconds/60) + 5)`.
  Generalise `completeWebhook` to take the source's bound; unfiltered
  `aws_firehose` uses `sampling: none`; a source declared filtered
  (`declared_filtered boolean`, set when the user picks the Lambda option)
  stays `partial`.
- Filter Lambda template `frontend/apps/docs/public/templates/citeladder-firehose-filter.mjs`
  generated by a new `scripts/export-firehose-filter.ts` from `crawlers.json`
  (embeds `catalog_version`, lowercase substring match on `cs(User-Agent)`,
  returns `Ok`/`Dropped` per record). Add `crawl:firehose-filter --check` and
  wire it into `scripts/quality.mjs` beside `crawl:worker --check`.
- Setup dialog (`crawl-log-setup.tsx` + `lib/config/crawl-logs.ts`
  `CRAWL_LOG_SETUPS`): new AWS option with generated steps: Firehose stream in
  us-east-1, HTTP endpoint URL, access key = token, GZIP, buffer 1–3 MiB,
  interval 60–300 s (input stored as `buffer_interval_seconds`), retry 3600 s,
  S3 backup failed-only; CloudFront logging → Firehose → JSON → the eight
  fields; notes: ~4 h first delivery, console demo data shows as unsupported
  format, test with a real visit; optional filter Lambda download.
